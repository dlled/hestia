# MCP 2026-07-28 integrity profile

## Purpose

HESTIA exposes a private MCP ingress for policy-mediated ecosystem clients. The gateway is deliberately separate from Edge HTTP APIs and from model-provider egress.

## Wire contract

- Protocol version: `2026-07-28`.
- Transport: stateless Streamable HTTP at `POST /mcp`.
- Discovery: `server/discover`; legacy `initialize` negotiation is rejected.
- Every request carries `MCP-Protocol-Version` and `Mcp-Method`; named primitive calls also carry `Mcp-Name`.
- Header/body disagreement returns JSON-RPC error `-32020` with HTTP 400.
- Unsupported protocol versions return `-32022`.

## Integrity and exposure controls

- Separate read-only and automation bearer credentials are mandatory.
- Token comparison is constant-time.
- Host and Origin allowlists reject DNS rebinding and cross-origin browser requests.
- The gateway binds to loopback by default; Compose only exposes it to the internal network.
- Request state uses the SDK HMAC-SHA256 codec, an explicit TTL, constant-time verification, and a binding composed from the MCP method and authenticated client identifier.
- Tampered, expired, wrong-method, or wrong-principal state is rejected before tool execution.

Read tools expose system status, canonical home entities and incidents. `hestia.automation.start` is effectful and therefore requires the automation scope plus explicit multi-round-trip confirmation. Its signed state carries the immutable plan reference and a nonce that is consumed once before submission to the policy-mediated Temporal path. Raw Home Assistant calls, provider calls, shell and SQL are prohibited.

## Verification

The integration suite covers discovery, tool listing/calling, missing authentication, forbidden origins, header/body mismatch, and tampered request state. Container contract tests enforce empty example secrets and the private network deployment.
